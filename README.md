# 🔮 Предсказатель будущего: направление цены крипты на 24ч

Прототип: Django REST API + Vue 3 SPA. Прогнозирует, вырастет/упадёт/останется на месте
цена крипто-актива (BTC, ETH, SOL, XRP, DOGE) в ближайшие **24 часа**, на основе прозрачного
weighted-scoring алгоритма (без "чёрного ящика" ML и без реальных денег/ставок).

## 1. Тема

**Крипторынок: краткосрочное направление цены (UP / DOWN / FLAT) на горизонте 24ч.**
Выбрана потому что для неё легко достать два независимых бесплатных источника данных без
ключей и подписок, а рынок достаточно ликвиден, чтобы алгоритмическая логика (моментум +
новостной фон) имела экономический смысл.

## 2. Источники данных (2 реальных, без платных ключей)

| Источник                                             | Тип         | Что берём                                                                                                   |
| ---------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------- |
| **CoinGecko API** (`api.coingecko.com/api/v3`)       | Цены/объёмы | текущая цена, объём торгов за 24ч, капитализация, `usd_24h_change`, история цены за 8 дней (`market_chart`) |
| **RSS крипто-СМИ**: CoinDesk, Cointelegraph, Decrypt | Новости     | заголовок, описание, дата публикации, ссылка                                                                |

Оба источника бесплатны и не требуют API-ключа/подписки.

## 3. Как устроена база (Django ORM, `predictor/models.py`)

Цепочка **источник → сырые данные → нормализованные показатели → прогноз → история проверки**:

- `Source` — реестр источников (CoinGecko, CoinDesk, Cointelegraph, Decrypt).
- `Asset` — объект прогноза (актив: BTC, ETH, SOL, XRP, DOGE).
- `RawPriceRecord` — сырой ответ CoinGecko на каждый опрос (цена, объём, капа, `raw_json`).
- `NewsArticle` — сырая новость из RSS + посчитанная тональность + `mentioned_assets` (M2M).
- `NormalizedMetric` — производные показатели, посчитанные из сырых данных:
  `MOMENTUM_24H`, `MOMENTUM_7D`, `VOLUME_CHANGE_24H`, `VOLATILITY_7D`,
  `NEWS_SENTIMENT_AVG`, `NEWS_VOLUME_48H` (количество новостей — всегда целое число,
  см. `NormalizedMetric.value_display`).
- `Prediction` — сам прогноз: направление, вероятность роста, уверенность, риск,
  аргументы, полная раскладка скора (`score_breakdown`, JSON).
- `PredictionOutcome` — факт по истечении 24ч: сбылся прогноз или нет (см. п.6).
- `DataFetchLog` — **история обновлений**: каждый запуск сбора данных по каждому источнику
  (успех / частично / ошибка, сколько записей).

## 4. Алгоритм (`predictor/services/scoring.py`) — как считаются цифры

Никакого ML "чёрного ящика" — понятная взвешенная формула, полностью описанная в docstring файла:

1. Берём 4 нормализованных сигнала актива: `momentum_24h`, `momentum_7d`, `volume_change_24h`,
   `news_sentiment_avg`.
2. Каждый (кроме sentiment, он уже в [-1,1]) сжимаем в диапазон `[-1, 1]` через
   `tanh(значение / масштаб)` — масштабы подобраны под типичную волатильность крипты
   (5% для суточного моментума, 10% для недельного, 20% для объёма).
3. Взвешенная сумма:

   ```
   raw_score = 0.35·momentum_24h + 0.15·momentum_7d + 0.15·volume_change + 0.35·news_sentiment
   probability_up = clip((raw_score + 1) / 2, 0.05, 0.95)
   ```

4. `direction`: UP если `probability_up > 0.55`, DOWN если `< 0.45`, иначе FLAT.
5. `confidence` (уверенность **в самом прогнозе**, отдельно от вероятности роста) =
   доля сигналов, согласных с направлением (`signal_agreement`) + штраф за нехватку данных
   (мало новостей, нет истории цены).
6. `risk_level` считается из волатильности за 7д (`std` дневных доходностей) и количества
   новостей: высокая волатильность или < 2 новостей за 48ч → риск HIGH; противоречащие друг
   другу сигналы → риск как минимум MEDIUM.
7. `arguments` — текст, построчно показывающий вклад каждого сигнала в итоговый скор
   (сырое значение → нормализованное → вклад с учётом веса), чтобы можно было руками
   проверить, что цифры сходятся.

Пример (реальный вывод алгоритма на демо-данных BTC):

```
Итоговый скор = +0.512 -> вероятность роста 75.6%. Разбивка по сигналам:
- Momentum цены (24ч): сырое значение 3.20, вклад в скор +0.198 (в пользу роста, вес 0.35)
- Momentum цены (7д): сырое значение 8.50, вклад в скор +0.104 (в пользу роста, вес 0.15)
- Изменение объёма торгов (24ч): сырое значение 0.00, вклад в скор +0.000 (нейтрально, вес 0.15)
- Тональность новостей (48ч): сырое значение 0.60, вклад в скор +0.211 (в пользу роста, вес 0.35)
Новостей за 48ч учтено: 3. Согласованность сигналов с направлением: 75%.
```

`0.198 + 0.104 + 0.000 + 0.211 = 0.512` — цифры в карточке прогноза считаются напрямую из
сохранённых `NormalizedMetric`, а не генерируются отдельно.

### Анализ тональности новостей (`predictor/services/sentiment.py`)

Без внешних AI-API: лексиконный подсчёт (списки позитивных/негативных слов crypto-домена,
`(pos - neg) / (pos + neg)`). Прозрачно и воспроизводимо — можно открыть код и увидеть, почему
конкретная новость получила такую оценку. Более свежие новости весят больше
(экспоненциальное затухание с полураспадом 24ч) при усреднении `news_sentiment_avg`.

## 5. Риск и уверенность — не просто "да/нет"

Каждая карточка прогноза содержит:

- **Вероятность роста** (число 0.05–0.95, никогда не 100%/0%).
- **Уверенность модели** — насколько сигналы согласованы и достаточно ли данных.
- **Уровень риска** (LOW/MEDIUM/HIGH) с текстовым объяснением причин (волатильность,
  мало новостей, противоречивые сигналы).
- **Аргументы** — построчная раскладка вклада каждого показателя.

## 6. Как система понимает, что ошиблась (`predictor/services/evaluation.py`)

Через 24ч после создания прогноза (`horizon_hours`) команда `evaluate_predictions`:

1. Заново запрашивает текущую цену актива в CoinGecko.
2. Сравнивает с ценой на момент прогноза → `actual_pct_change`.
3. Определяет факт: `UP` если рост >0.5%, `DOWN` если падение >0.5%, иначе `FLAT`
   (мёртвая зона 0.5%, чтобы шум не считался ошибкой).
4. `was_correct = predicted.direction == actual_direction`.
5. Считает `probability_error = |probability_up − факт(0/1)|` — компонент **Brier Score**:
   это показывает не просто "угадал/не угадал", а насколько **калибрована** модель
   (уверенно ли она ошибалась).
6. Всё сохраняется в `PredictionOutcome`, агрегат доступен на `/api/model-health/`
   (`hit_rate`, `avg_brier_component`) и показан в шапке интерфейса.

## 7. Что использовано из AI

Тестовое задание выполнялось с помощью Claude (Anthropic) — backend/frontend,
архитектура БД, формула скоринга и её веса продуманы и написаны с помощью AI-ассистента
в чат-интерфейсе (доступ к отдельным AI-API типа GLM в рамках задания не использовался).
Сам работающий прототип **не обращается к LLM во время выполнения** — тональность новостей и
скоринг считаются детерминированными, объяснимыми алгоритмами (лексикон + взвешенная сумма),
специально чтобы прогноз можно было на 100% проверить вручную по сохранённым в БД цифрам.

## 8. Дисклеймер

⚠️ Прогнозы носят исключительно демонстрационный/учебный характер. Реальные деньги,
ставки или брокерские API **не подключаются**. Проект не гарантирует и не обещает доходность,
не является финансовой рекомендацией.

## Управление через админку Django

Админка (`/admin/`) — это не только просмотр таблиц, но и рабочий пульт управления сбором
данных, без консоли:

- **Криптовалюты (токены)** — список показывает текущую цену и последний прогноз по каждому
  активу. Отметьте одну или несколько монет галочкой (или «выделить все» сверху таблицы —
  это и есть режим «по всем монетам») и в выпадающем списке действий выберите:
  - **① Собрать цены** — цена/объём/капа + история за 8 дней + сразу считаются
    `momentum_24h`, `momentum_7d`, `volume_change_24h`, волатильность. Отдельно жать
    «рассчитать метрики» не нужно — это встроено прямо в сбор цен.
  - **② Собрать новости** — RSS-лента не привязана к одной монете, поэтому новости всегда
    собираются по всем источникам сразу, но тональность/счётчики пересчитываются для
    выбранных активов.
  - **③ Сделать прогноз** — считает `Prediction` только для выбранных монет.
  - **🔁 Полный цикл** — цены + новости + прогноз одним кликом.
- **Добавление нового токена**: откройте «Криптовалюты (токены)» → «Добавить», укажите
  тикер, название и **ID на CoinGecko** (это часть адреса страницы монеты на coingecko.com,
  например `bitcoin`, `solana`, `chainlink`). После сохранения данные по цене для него
  собираются автоматически (see `AssetAdmin.save_model`) — не нужно отдельно жать «Собрать
  цены» сразу после создания.
- **Добавление своего RSS-источника**: «Источники данных» → «Добавить», тип — «RSS-лента
  новостей», укажите адрес ленты. Она автоматически подключится к следующему сбору новостей
  (кнопка «Собрать новости» — на странице «Новости» или через действия у токенов) — все RSS
  из базы данных участвуют в сборе, а не только 3 стандартных.
- **Проверка прогнозов (сверка с фактом)**: кнопка «Проверить прогнозы» на странице
  «Прогнозы». Также сверка запускается **автоматически** при каждом новом расчёте прогноза
  (см. `generate_predictions()` в `scoring.py`) — не нужно помнить о ней отдельно.
- Все поля во всех разделах админки подписаны **по-русски** (тикер, цена, объём торгов,
  уверенность модели, уровень риска и т.д.) — задаётся через `verbose_name` в `models.py`.

## API для проверки / тестирования

Эти эндпоинты дублируют кнопки админки по HTTP — удобно дёргать из Postman/curl без захода
в браузер. В проде их стоит закрыть авторизацией, в прототипе они открыты для простоты.

| Метод | URL                                        | Что делает                                      |
| ----- | ------------------------------------------ | ----------------------------------------------- |
| POST  | `/api/actions/fetch-prices/`               | Собрать цены по всем активам                    |
| POST  | `/api/actions/fetch-prices/?asset=<id>`    | Собрать цены по одному активу                   |
| POST  | `/api/actions/fetch-news/`                 | Собрать новости по всем RSS-лентам              |
| POST  | `/api/actions/run-predictions/`            | Прогноз по всем активам                         |
| POST  | `/api/actions/run-predictions/?asset=<id>` | Прогноз по одному активу                        |
| POST  | `/api/actions/evaluate/`                   | Сверить прогнозы с истёкшим горизонтом с фактом |
| POST  | `/api/actions/run-cycle/`                  | Полный цикл: цены → новости → сверка → прогноз  |
| POST  | `/api/actions/run-cycle/?asset=<id>`       | Полный цикл по одному активу                    |

Пример проверки:

```bash
curl -X POST http://localhost:8000/api/actions/run-cycle/
curl -X POST "http://localhost:8000/api/actions/run-predictions/?asset=1"
```

## Как запустить

### Вариант 1 — Docker (проще всего)

```bash
docker compose up --build
```

- Backend поднимется на `http://localhost:8000` (миграции применяются автоматически при
  старте контейнера), frontend — на `http://localhost:5173`.
- База (sqlite) хранится в именованном Docker volume `backend_db`, данные переживают
  пересборку образа.
- После первого запуска создайте суперюзера для админки:
  ```bash
  docker compose exec backend python manage.py createsuperuser
  ```
- Соберите данные и прогнозы через админку (`/admin/`) или API-действия выше — либо
  разово через `docker compose exec backend python manage.py run_cycle`.

### Вариант 2 — вручную

#### Backend (Django)

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate

# 1) собрать сырые данные (CoinGecko + RSS)
python manage.py fetch_data

# 2) посчитать прогнозы из собранных метрик
python manage.py run_predictions

# 3) (через 24ч+) проверить прогнозы фактом
python manage.py evaluate_predictions

# либо всё сразу одной командой (удобно повесить в cron раз в час)
python manage.py run_cycle

python manage.py runserver 0.0.0.0:8000
```

API будет на `http://localhost:8000/api/` — эндпоинты:
`assets/`, `predictions/?asset=<id>`, `news/?asset=<id>`, `metrics/?asset=<id>`,
`fetch-logs/`, `model-health/`. Админка Django — `/admin/` (создайте суперюзера через
`createsuperuser`), там видно все таблицы: источники, сырые записи, метрики, прогнозы, лог обновлений.

#### Frontend (Vue 3 + Vite)

```bash
cd frontend
npm install
npm run dev
```

Откройте `http://localhost:5173`. Frontend обращается к API на `http://localhost:8000/api/`
(см. `src/api.js`).

### Важно про CoinGecko

Публичный API CoinGecko иногда лимитирует запросы по IP (в т.ч. может быть недоступен из
некоторых облачных/CI-сред — код это корректно ловит и пишет `FAILED` в `DataFetchLog`,
приложение не падает). Для локального запуска с домашнего/рабочего интернета работает штатно.
Если лимит всё же словили — подождите минуту или уменьшите список активов в
`config/settings.py -> PREDICTOR_ASSETS`.
